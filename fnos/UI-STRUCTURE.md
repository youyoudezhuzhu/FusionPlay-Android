# FusionPlay fnOS 管理界面：v2 结构与交互说明

> 当前实现版本：`0.2.0`。代码：`fnos/frontend/`（纯 HTML/CSS/原生 JS，无框架、无构建、无 CDN）。
> 后端 API 契约见 `fnos/ARCHITECTURE.md`；验证记录见 `fnos/VERIFICATION.md`。
> 本文描述 **v2 四页面** 的信息架构、交互与数据绑定；旧版五页面/全局曲线文档已废弃。

---

## 1. 概览

| 项 | 值 |
|---|---|
| 定位 | 音频接收器与多音箱输出管理面板，不是独立播放器 |
| 页面 | 四个：概览 / 音频 / 接收 / 设置；hash 路由 `#/overview` `#/audio` `#/receive` `#/settings` |
| 技术 | `index.html` + `style.css` + `js/{core,store,curve,page-overview,page-audio,page-receive,page-settings,main}.js` |
| 主题 | 浅色 / 深色 / 跟随系统（localStorage `fusionplay.theme`，`data-theme` + `prefers-color-scheme`） |
| 部署 | 兼容 fnOS iframe 网关 `/app/fusionplay-fnos/` 与开发根路径；静态资源相对路径 |
| 轮询 | `/api/status` + `/api/config` 2s；`document.hidden` 暂停；编辑中的脏字段不被覆盖 |
| 图标 | 内联 SVG sprite（12 个），无 emoji / 无在线图标库 |

设计 token（CSS 变量，浅色/深色两套）：页面背景、卡片、次级背景、主/次文字、边框、强调色、
选中背景、正常状态色；主内容 `max-width:1050px`，主卡圆角 15px、设备卡 11px、按钮 9px，
页面标题 22px、卡片标题 14px、正文 13px、辅助 11–12px。

## 2. 全局框架

```
┌ topbar ────────────────────────────────────────────────────────────────┐
│ [蓝色圆角图标] FusionPlay                         ● 服务运行状态  [主题] │
│                 音频接收与输出管理                                       │
├ 导航 ──────────────────────────────────────────────────────────────────┤
│   概览     音频     接收     设置          （选中：蓝字 + 底部蓝色细线）  │
├ main（max-width 1050px）────────────────────────────────────────────────┤
│  页面标题 + 副标题                                                       │
│  卡片内容 …                                                             │
├ 底部保存栏（仅有未保存修改时出现）──────────────────────────────────────┤
│  ● 有未保存修改 · 音频/接收           [撤销]  [保存并应用]               │
└────────────────────────────────────────────────────────────────────────┘
```

- 服务状态来自 `/healthz` + `/api/status`；断线显示状态变化与 toast，不伪造“正常”。
- 主题按钮循环：跟随系统 → 浅色 → 深色；切换后 canvas 曲线按当前主题重绘。
- 保存栏为 body 预留空间，不遮挡曲线/设备列表；移动端同样固定底部。

## 3. 概览（`#/overview`）

标题「概览」，副标题「一个接收器，连接所有声音。」桌面双栏：

| 区域 | 内容 | 数据 |
|---|---|---|
| 左·当前接收 | 播放/待机状态、音源协议 chip、封面（发送端提供才显示，否则占位图标）、标题、艺术家、专辑/格式/时长、进度（position 与 duration 都存在才画）；**发送端逻辑主音量只读**；无媒体显示「等待音频投放 / 使用手机选择 FusionPlay」 | `status.current_source`、`status.media`、`status.sender_volume` |
| 左·音频输出 | 已启用音箱数、在线/输出状态、当前输出摘要、「管理音箱」入口（跳 `#/audio`） | `status.devices` + `config.audio.devices` |
| 右·接收协议 | AirPlay 2 / DLNA / 小米妙播，真实状态标签、简短详情 | `status.protocols.*` |
| 右·服务状态 | 是否正常、需要关注的问题（离线设备/协议错误/`last_error`）摘要 | `status.errors/last_error`、设备在线状态 |

概览**不展示**缓冲深度、drift_ppm、underrun、原始日志等工程参数。

## 4. 音频（`#/audio`）

标题「音频」，副标题「选择输出音箱，分别调整每个设备的音量响应与播放同步。」
桌面左右双栏 ≈ 0.85 : 1.25；移动端单列（设备列表 → 点击进入该设备详情，带返回按钮）。

### 左栏

**输出设备列表**（每设备一张小卡片，非表格）

```
┌ ● [图标] USB Audio DAC          [在线]  [开关] ┐
│           USB Audio · hw:CARD=ultra,DEV=0      │
└────────────────────────────────────────────────┘
  选中卡：浅蓝背景 #EDF2FF + 蓝色边框 #4A70D5
```

- 点卡片 = 选中编辑（右侧切换）；点开关 = 是否参与输出。两者独立，可多设备同时启用。
- 离线设备保留在已配置列表：显示「离线」，可删除配置；绝不显示为正常播放。
- 「刷新设备」→ `GET /api/devices`；可把新发现的在线设备加入配置（保存后生效）。
- 启用/删除/新增只改草稿，统一保存后生效。

**全局设置**（只有两项）

- 全局输出衰减：0–100%，默认 100%（100 = 不额外衰减）。
- 所有输出静音：全局开关，不改变发送端显示的主音量。
- 说明文字：「用于整体降低音量，不修改手机端显示的主音量。」
- 这里**没有**音量曲线。

### 右栏（选中设备）

顶部：设备名称、类型、运行状态。

**音频校准**

1. 响度平衡：滑块 −30–0 dB（默认 0），显示当前值 + 简短说明。
2. 同步延迟补偿：0–2000 ms，滑块 + 精确数字输入（可键盘输入）。
3. 独立音量曲线：标题 + 「当前音箱」标签；四个预设按钮「线性 | 柔和 | 均衡 | 自定义」
   （选中：浅蓝底/蓝字/蓝边）；曲线图（清晰坐标轴、细网格、蓝色曲线、横轴发送端音量 0–100%、
   纵轴当前音箱输出幅度 0–100%）；**只有选「自定义」**才显示编辑控件：
   添加控制点、删除中间点、拖动、精确数值输入、方向键微调、重置、单调约束；
   首尾固定 `(0,0)` 与 `(1,1)`；预览去抖调用 `POST /api/calibration/preview`，
   旁注「曲线为理论映射，不是声压测量」。
4. 输出设备测试：「测试音」→ `POST /api/devices/test {id}`（真实 1s 测试音；null 后端会如实提示不会发声）。
5. 高级音频参数（默认折叠）：ALSA 设备 ID、首选采样率（0=跟随设备）、声道、实际格式、
   缓冲深度、时钟漂移、underrun、已写帧、支持的采样率等后端实际字段。

### 保存流程

`PUT /api/config`（完整配置）→ 音频域有改动时 `POST /api/devices/refresh` → 重读 `/api/devices`。
保存成功后以服务端响应为新基线；失败保留草稿。

## 5. 接收（`#/receive`）

标题「接收」，副标题「一个统一名称，三种接收协议。」

- **接收器信息**：接收器名称（`config.receiver.name`）、网络接口（`config.receiver.interface`，空=自动）。
  两者各只出现一次，三协议共享。
- **接收协议**：三行 AirPlay 2 / DLNA / 小米妙播，每行：名称、简短说明、真实运行状态、启用开关。
  端口、客户端数、详情放入可展开区。
- 保存：`PUT /api/config`；若名称/接口/协议开关变化，后端会重启协议宿主（1–3s），
  UI 显示「正在保存并重启接收服务…」，随后轮询 `/healthz` + `GET /api/config` + `/api/status`
  确认名称、接口、协议开关与运行时状态；失败/未生效如实提示，不显示假进度。

---

## 6. 设置（`#/settings`）

标题「设置」，副标题「应用维护、配置备份与诊断。」

- **应用信息**：版本、运行状态、音频后端（`status.audio.mode`）、日志级别（可切换 `POST /api/logs/level`）。
- **配置管理**：导出（`GET /api/export`，JSON 下载）、导入（`POST /api/import`；旧版 v1 导出会在
  客户端/服务端迁移为每设备曲线）；导入前提示兼容说明。
- **高级诊断**（折叠）：
  - 音频引擎统计（master_frames/dropped_frames/设备 underrun 汇总）
  - 网络接口 + `/proc/asound/cards` / `pcm`
  - 运行日志：搜索、级别过滤、复制、下载（`GET /api/logs?lines=N`，1–500 行）
  - 故障信息（`status.errors` / `last_error`）

## 7. 草稿与保存状态机

- 单一 `draftConfig`（来自最新 `GET /api/config`）+ 脏字段集合（receiver / protocols / audio 全局 /
  `audio.device|<id>|<field>` / 设备增删结构）。
- 轮询合并：只把**非脏**字段从服务端刷新回 draft；正在编辑的输入框/滑块/曲线不被覆盖；
  设备卡片按 id 增量更新，不重建节点、不丢焦点/选中状态。
- 页面切换/设备切换：draft 保留。
- 撤销：恢复最近一次保存成功的 baseline；保存成功：adopt 服务端响应并清空脏标记；
  保存失败：保留草稿并显示错误；协议保存超时/未生效：提示失败并保留可重试。
- 没有修改时保存栏隐藏。

## 8. 响应式

| 断点 | 行为 |
|---|---|
| > 920px | 四页水平导航；音频双栏（设备列表 + 设备设置同时可见）；曲线占满右栏 |
| ≤ 920px | 音频单列：设备列表在前，点击设备进入详情（返回按钮）；概览双栏变单列 |
| ≤ 720px | 收紧页面 padding、卡片 padding；保存栏全宽 |
| ≤ 560px | 导航紧凑（四入口仍在）；表单/滑块保持足够触控面积；无横向宽表格 |

曲线使用 pointer events + `touch-action:none`，手机可拖动控制点；精确数值输入在自定义编辑器中。

## 9. 与后端的数据契约（前端实际消费）

- `GET /api/status`：协议状态、当前音源/媒体、发送端音量、设备运行态、音频统计、错误。
- `GET /api/config`：`config_version`、receiver、protocols、`audio.{global_attenuation_percent,muted,devices[].{id,name,enabled,gain_db,delay_ms,sample_rate,curve}}`、logging。
- `GET /api/devices`：ALSA 实测设备（稳定 ID、采样率、通道、在线、默认）。
- `POST /api/devices/refresh`、`POST /api/devices/test`。
- `POST /api/calibration/preview`：按 `{device_id}` 或 `{curve}` 返回 101 点，前端绘图。
- `GET/POST /api/logs*`、`GET /api/export`、`POST /api/import`、`GET /api/diagnostics`、`GET /healthz`。

前端**不**展示/不使用 v1 的全局 `audio.curve`；该字段仅用于旧配置迁移兼容。

## 10. 已知边界（如实）

- 无浏览器环境，未做真实截图/像素级视觉验证；浅色/深色实际观感、360/390/768/1024 布局、
  移动端触摸拖拽需真机/浏览器确认。
- 真实 ALSA 多音箱输出、延迟/漂移听感、AirPlay 2 / DLNA / 小米妙播真实发送端未在 UI 层面验证
  （协议层验证见 `VERIFICATION.md`）。
- 图表面板显示的是**理论映射**，不是声压测量；无麦克风校准功能。
- 本版不支持每设备独立曲线以外的全局曲线；旧全局曲线仅迁移一次。
